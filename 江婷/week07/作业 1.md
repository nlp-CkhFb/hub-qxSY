# 抽取任务对比实验报告：金融公告 → 医学临床发现事件的跨领域迁移

## 一、实验目的

课程要求：**更换数据集，对抽取任务的各种方法做对比实验，分析效果差异**。

本实验把老师提供的 **金融公告事件抽取** 数据换成 **医学临床发现事件抽取** 数据（CHIP-CDEE），
在项目统一的评测口径下，完整复现老师的六层方法链路（规则 / BiLSTM-CRF / BERT 联合 /
消融实验 / LoRA 微调 / CRF 硬约束），回答三个问题：

1. **换领域后，各方法表现如何？** 领域知识写在代码里的方法（规则）是否比从数据学的方法（模型）更脆弱？
2. **给规则补上医学词典，能救回多少？**（领域适配的收益）
3. **预训练深度、解码器、输入长度、解码约束各自值多少个点？**（消融实验）

---

## 二、数据集

| 项目 | 老师数据（DuEE-Fin 金融公告） | 本实验数据（CHIP-CDEE 临床发现） |
|---|---|---|
| 领域 | 金融公告 | 医学 / 电子病历 |
| 事件类型数 | 13 | 1（临床发现） |
| 角色数 | 61 去重 / 92 槽位 | 3（描述词 / 解剖部位 / 发生状态） |
| 训练规模 | 5747 句 | 2070 句 |
| dev 规模 | 930 句 | 518 句 |
| 平均句长 | ~164 字 | ~94 字（中位 74） |

**数据来源**：CBLUE / `Juvenilecris/chinese-med` 的 CHIP-CDEE 子任务（Clinical Discovery Event Extraction），
许可 Apache-2.0。原始 92MB JSON 中筛出事件抽取样本，转换为项目统一的 JSONL 格式
（主体词→触发词，描述词/解剖部位/发生状态→角色），按句 8:2 切分，seed=42。

**格式契约**：一行 = 一句话 + 恰好 1 个事件，评测按 `id|sent_id` 对齐，与老师数据完全一致。
数据一致性自检：gold-vs-gold 三项 F1 均为 1.0000。

---

## 三、实验设置

- **统一的评测函数**：`common/evaluate_events.py`，所有方法共用同一把尺子（未作任何修改）。
- **评测集**：判别式方法用 dev 全量 518 行；LoRA 用 dev 的 100 条固定子集（seed=42），分别标注。
- **硬件**：Apple M5，MPS 加速（LoRA 用 fp32）。
- **训练配置**：BiLSTM 12 epoch；BERT 系列 4 层 / 6 epoch（12 层版 4 epoch）；
  max_len 默认 128（消融版 256）；batch 32。LoRA 用 Qwen2.5-0.5B、r=8、900 条、1 epoch。

### 方法清单（对齐老师六层链路）

| 层级 | 方法 | 脚本 | 改动 |
|---|---|---|---|
| L0 | 规则·未适配 | `rule/run_rule.py` | 无 |
| L0 | 规则·医学适配 | `rule/run_rule_homework.py` | 领域词典 |
| L1 | 字符级 BiLSTM-CRF | `bilstm_crf/train.py` | 无（换数据） |
| L2a | BERT+Linear | `bert/train.py --decoder linear` | 无（换数据） |
| L2a | BERT+CRF | `bert/train.py` | 无（换数据） |
| L2a | BERT+CRF + 触发词回填 | `eval/postprocess_trigger_copy.py` | 后处理，不重训 |
| L2 技巧 | CRF 硬约束解码 | `bert/evaluate_hard_constraint_homework.py` | 只改解码 |
| 消融 | max_len 256 / BERT 12 层 | `bert/train.py` | 旋钮调整 |
| L4 | LoRA SFT（Qwen2.5-0.5B） | `llm_lora/train_sft_homework.py` | 基座/数据/prompt 适配 |

> L2b 两段式、L5 系统组合依赖 detect / 篇章级数据（本数据只有句级事件抽取），
> 且医学只有 1 类事件，"类型分类"那一段无区分度，本次未纳入。
> L3 API 提示（zero/few-shot）需要外部 API key，本次未纳入，报告中只做方法层面的定性对比。

## 四、实验结果

### 4.1 主表：判别式方法（dev 518 全量）

| # | 方法 | trigger F1 | argument F1 | event_exact F1 | 训练耗时 |
|---|---|---|---|---|---|
| 1 | L0 规则·未适配 | 0.6039 | 0.0000 | 0.0796 | 0（秒级） |
| 2 | L0 规则·医学适配 | 0.6039 | 0.3191 | 0.0039 | 0（秒级） |
| 3 | L1 BiLSTM-CRF | **0.8701** | **0.7214** | **0.5965** | 116 s |
| 4 | L2a BERT+Linear | 0.7859 | 0.5387 | 0.3595 | 160 s |
| 5 | L2a BERT+CRF | 0.7842 | 0.5196 | 0.3547 | 232 s |
| 5b | L2a BERT+CRF + 触发词回填 | 0.7842 | 0.5196 | 0.3547 | 0（复用） |
| 5c | L2 技巧 CRF 硬约束 | 0.8143 | 0.6087 | 0.4131 | 0（复用） |
| 6 | L2a BERT+CRF（max_len 256） | 0.7874 | 0.5153 | 0.3543 | 966 s |
| 7 | L2a BERT+CRF（12 层） | 0.8379 | 0.6380 | 0.4688 | 722 s |

> 加粗为该列最高值。所有行用同一评测函数、同一 dev 518 行，对比公平。
> BiLSTM-CRF 三项均为全场最优，且零代码改动。

## 五、结果分析

### 1. 领域知识写死在代码里的方法，跨领域失效最彻底

规则未适配版 trigger 0.6039 基本保持（触发词词典从 train 统计，天然适配），
但 **argument 直接归零**：原版角色抽取器靠角色名里的"金额/日期/比例/公司"选正则，
医学的"描述词/解剖部位/发生状态"一个都匹配不上，一个论元都不敢抽（tp=0、fp=0）。
补上领域词典后 argument 回到 0.3191——这就是"领域词表"本身值的分。

### 2. 从数据学习的方法天然可迁移，零代码改动

BiLSTM-CRF 只换 `--data_dir` 就拿到 trigger 0.8701 / argument 0.7214 / event 0.5965，
三项全场最高。序列标注从数据里学边界，不依赖领域词典，跨领域迁移成本最低。
它甚至超过了 BERT+CRF（0.5196 argument）——在小数据 + 短句场景下，字符级模型边界更稳。

### 3. 预训练深度是最关键的旋钮

| 对照 | trigger | argument | event |
|---|---|---|---|
| BERT 4 层（hw_bert_crf） | 0.7842 | 0.5196 | 0.3547 |
| BERT 12 层（hw_bert_12L） | **0.8379** | **0.6380** | **0.4688** |

12 层比 4 层 argument +11.8pp、event +11.4pp，印证老师的结论：
**预训练深度对"角色边界"很关键**，4 层只省一半算力却损失最多的是论元边界。

### 4. CRF vs Linear：软约束下收益小，硬约束才见真章

| 对照 | trigger | argument | event | 推理延迟 |
|---|---|---|---|---|
| BERT+Linear | 0.7859 | **0.5387** | **0.3595** | 3.74 ms/句 |
| BERT+CRF（软约束） | 0.7842 | 0.5196 | 0.3547 | 40.92 ms/句 |

本次数据句子短、结构规整，软约束 CRF 并未超过 Linear——这和老师金融数据上
CRF 略优的结论不同（老师数据长句多、span 重叠多）。但加上硬约束后：

| 对照项 | 软约束 | 硬约束 |
|---|---|---|
| 非法序列（句） | 196 | **3** |
| 非法转移（处） | 358 | **8** |
| trigger F1 | 0.7842 | **0.8143** (+0.0301) |
| argument F1 | 0.5196 | **0.6087** (+0.0891) |
| event_exact F1 | 0.3547 | **0.4131** (+0.0584) |

**关键结论**：约束是准确率的一部分。不重训、只改解码，非法序列 196→3 句，
三项指标全线免费上涨。模型收敛越充分，约束价值越大。

### 5. max_len 在本数据上不是瓶颈

| 对照 | trigger | argument | event |
|---|---|---|---|
| max_len 128 | 0.7842 | 0.5196 | 0.3547 |
| max_len 256 | 0.7874 | 0.5153 | 0.3543 |

几乎无差别。原因是医学句长中位只有 74 字，128 已覆盖 79.7% 的句子；
老师金融数据句长中位 164 字、128 截断 68.7%，所以他的 length 消融掉 3.76pp。
**同一个旋钮在不同领域的重要性完全不同**。

### 6. 触发词回填后处理在本数据上无效

从 train 学到 0 条"角色=触发词"回填规则——因为医学触发词是"肿瘤""结节"这类主体词，
与角色（描述词/部位/状态）几乎不重叠；老师金融数据里"变动类型"角色与触发词高度重叠，
所以那套回填能涨分。**后处理规则同样领域相关，不能跨领域照搬**。

### 7. LoRA 微调：小模型 + 少数据也能学到结构化抽取

LoRA SFT（Qwen2.5-0.5B）在 100 条上 trigger 0.7437 / argument 0.3926 / event 0.1709，
JSON 合法率 100%。注意训练时 max_length 必须 ≥ 900（医学 prompt 中位 517 token、
p95 619），否则大量样本被截断、输出格式崩坏——这与老师踩的 max_length 坑一致。
生成式方法的优势是适配成本低（改 prompt / 微调即可），短板是边界精度：
event_exact 0.1709 仍低于判别式 BiLSTM 的 0.5965。

## 六、局限与说明

1. 医学数据只有 1 类事件（临床发现），老师是 13 类，"事件类型分类"维度无法对比。
2. L2b 两段式、L5 系统组合依赖 detect / 篇章级数据，本次未做；L3 API 提示需外部 key，未做。
3. LoRA 只用 100 条评测、基座 0.5B；老师的对应数字是 n=200、0.6B，不做严格横向排名。
4. BERT 系列用 4 层 / 6 epoch（12 层版 4 epoch）控制耗时，非老师全量配置。
5. 规则、BiLSTM、BERT 共用同一评测函数与 dev 全量 518 行，对比公平；
   只有"怎么抽"因方法而异，"怎么算分"完全一致。

---

## 七、结论

1. **领域耦合度决定迁移成本**：规则耦合最高（要改词典，未适配时 argument 归零）、
   BiLSTM/BERT 最低（换数据即可）、LoRA 需改基座/数据/prompt 但不用重写抽取逻辑。

2. **数据驱动的模型跨领域最稳**：BiLSTM-CRF 零代码改动拿到三项全场最高
   （0.8701 / 0.7214 / 0.5965），说明序列标注从数据学边界，不依赖领域词典。

3. **预训练深度 > 解码器 > 输入长度**：12 层比 4 层 argument +11.8pp（最关键）；
   CRF vs Linear 在短句数据上差异小；max_len 128→256 几乎无变化（领域差异所致）。

4. **解码约束是免费的质量提升**：CRF 硬约束不重训，非法序列 196→3 句，
   argument +0.089、event +0.058，模型越收敛收益越明显。

5. **生成式召回好、边界弱**：LoRA 在短句医学数据上 trigger 0.74、argument 0.39，
   但 event_exact 0.17 远低于判别式；生产上常见组合是"生成式抽候选 + 判别式修边界"。

**一句话总结**：换领域时，**代码的领域耦合度决定迁移成本**，**预训练深度决定边界质量**，
**解码期的结构约束是白捡的准确率**；而领域特性（句长、事件类型、角色与触发词的重叠度）
会直接改变每个旋钮的重要性——不存在跨领域通用的"最优配置"。
